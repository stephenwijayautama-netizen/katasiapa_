PRD — Website Game Kartu Percakapan
Versi 1.0 (draft untuk review) · 3 November 2026 · Nama produk sementara: “Kartu Game”
Intinya: website game kartu untuk anak muda ke atas. Pemain memilih tema,
mengocok atau men-spin kartu, membaca kata-kata di kartu, lalu mulai ngobrol. Isi
kartu bisa ditambah kapan saja lewat admin, tanpa coding.
1. Ringkasan Eksekutif
Produk ini terdiri dari tiga bagian yang saling terhubung:
1. Web App Pemain: landing page dark UI seperti foto referensi (hero besar + kipas
kartu), halaman tema, dan layar game dengan animasi kocok/spin.
2. Admin CMS: mengelola tema, kata-kata (isi kartu), aset karakter, pengguna, dan
statistik.
3. Studio Kartu: editor visual untuk membuat kartu, mengatur warna teks, lalu
mengekspor hasilnya.
Semuanya dibangun dari komponen React dengan satu sumber data: database
PostgreSQL. Kartu di game, preview di admin, gambar untuk dibagikan, dan hasil ekspor
dirender oleh komponen yang sama ( <ThemeCard> ), jadi tampilannya selalu konsisten.
Aspek Keputusan
Target pengguna Anak muda ke atas (17+), mobile-first
Tema awal Family, Love, Passion + Friendship, Dreams,
Gratitude; tema baru bisa ditambah dari admin
Mekanik utama Kocok (shuffle) dan Spin
Gaya visual Dark UI + kartu gradasi berani + karakter ilustrasi
beranimasi (kartu sudah didesain)
Stack yang direkomendasikan Next.js (React) + TypeScript + Tailwind + Framer
Motion; Supabase (PostgreSQL, Auth, Storage,
Realtime); Vercel
MVP Landing, game solo (kocok & spin), 6 tema, admin
CRUD + import kata-kata
Bahasa Indonesia dulu, Inggris di fase lanjut

2. Latar Belakang, Tujuan & Metrik Sukses
2.1 Masalah dan peluang
Kartu percakapan fisik mahal dicetak, isinya terbatas, dan sulit diperbarui. Versi web
bisa dimainkan gratis, diperbarui kapan saja, dan mudah dibagikan.
Pemilik produk perlu menambah kata-kata dan tema baru sendiri tanpa menunggu
developer.
Pengalamannya harus terasa seperti game (animasi, kejutan), bukan sekadar daftar
pertanyaan.
2.2 Tujuan
G1. Main cepat: dari landing ke kartu pertama dalam ≤ 3 klik.
G2. Landing page yang meniru gaya referensi (dark UI, hero besar, kipas kartu).
G3. Konten skalabel: tema, kata-kata, dan kartu baru ditambah lewat admin tanpa
coding.
G4. Satu sumber kebenaran tampilan kartu: data JSON → komponen <ThemeCard>
yang dipakai di game, admin, share, dan ekspor.
G5. Fondasi siap tumbuh (multiplayer, deck kustom, PWA) tanpa merombak database.
2.3 Di luar lingkup MVP
Pembayaran/marketplace deck, cetak kartu fisik otomatis, video/voice chat, aplikasi
native iOS/Android, dan fitur AI yang menjawab menggantikan pemain.
2.4 Metrik sukses
Angka di bawah adalah target awal (hipotesis) yang divalidasi setelah beta, diukur 3 bulan
setelah rilis.

Alur data mode solo
1. Setelah setup, klien mengunduh snapshot deck ( GET /api/decks/snapshot?
themes=… ): ID, kata-kata, level, dan bobot kartu berstatus published. Ukurannya kecil
(puluhan KB untuk 500 kartu) dan di-cache dengan ETag.
2. Kocok/spin dihitung di klien oleh game engine (cepat dan bisa offline). Hasil undian
ditentukan sebelum animasi dimulai.
3. Event (kartu ditarik, dilewati, disimpan) dikirim berkelompok ke POST /api/events .
4. Saat admin mem-publish kartu, versi snapshot naik. Pemain mendapat versi baru di sesi
berikutnya (cache maksimal 5 menit).
Mode room (fase 2) memakai server sebagai penentu urutan kartu agar semua perangkat
melihat kartu yang sama.

Alur utama
A. Pemain baru: Landing → Mulai Main → Setup (tema, level, nama pemain) → Game
board → kocok/spin → baca kartu → lanjut/lewati/simpan → Selesai (ringkasan + ajakan
bagikan atau masuk).
B. Dari kartu yang dibagikan: /c/[id]  → lihat kartu → Main tema ini.
C. Editor menambah kata-kata: Admin → Kartu → Tambah Massal → pilih tema dan level
→ tempel satu kata-kata per baris → preview kartu → simpan sebagai draft → review →
publish → muncul di game.
D. Admin membuat kartu visual: Studio Kartu → pilih tema/template → atur warna,
karakter, teks → cek kontras → simpan → ekspor atau publish.
E. Room (fase 2): Host membuat room → kode 6 karakter → teman bergabung lewat
kode/QR → host memulai → pemain bergiliran menarik kartu secara realtime.

Interaksi: hover/focus mengangkat kartu 16 px; klik membuka halaman tema;
drag/swipe memutar kipas dengan inertia (ini juga menjadi “spin” kecil di landing);
auto-rotate pelan tiap 6 dtk (berhenti saat pointer di atas kipas).
Karakter: animasi loop halus (napas, kedip, api, bintang) hanya pada kartu tengah;
kartu lain statis agar ringan.
Di bawah hero: (1) Pilih tema (grid 6 kartu + slot “segera hadir”), (2) Cara main 3 langkah
(Pilih tema → Kocok/Spin → Ngobrol), (3) cuplikan Level (Ringan, Dalam, Berani), (4)
penutup + CTA, (5) footer.
Mobile: navigasi atas hanya logo dan avatar; tab Main/Tema pindah ke bar bawah;
pencarian jadi ikon yang membuka overlay; kipas menjadi carousel geser (snap) dengan
kartu tengah dominan.
SEO dan berbagi: server-side rendering, judul/deskripsi/OG image (kipas kartu), data
terstruktur dasar.
8.3 Kriteria penerimaan
Tampilan desktop dan mobile mengikuti desain final yang disetujui.
Badge jumlah tema/kartu diambil dari database, bukan teks statis.
Mulai Main membuka /play ; kartu di kipas membuka /themes/[slug] .
LCP ≤ 2,5 dtk di 4G; CLS ≤ 0,1; JavaScript awal ≤ 180 KB gzip.
Dengan preferensi reduced motion, auto-rotate dan animasi loop dimatikan.
Teks memenuhi kontras WCAG AA (4,5:1); semua elemen interaktif bisa dipakai dengan
keyboard.
